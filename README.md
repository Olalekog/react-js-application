# React JS Application – Secure AWS 3-Tier Deployment

This repository deploys a secure, scalable AWS 3-tier application using **Terraform**, **GitHub Actions**, **Docker**, **EC2 Auto Scaling Groups**, **Application Load Balancers**, **Amazon RDS MySQL**, **AWS Secrets Manager**, **Route 53**, **ACM**, **KMS encryption**, and **local username/password authentication**.

The project is designed for a **single AWS account** with separate isolated VPCs for each environment.

```text
AWS Account: 866934333672
Region: us-east-1
Project Name: react-js-application

Environments:
  dev         -> vpc-dev         -> 10.20.0.0/16
  uat         -> vpc-uat         -> 10.10.0.0/16
  production  -> vpc-production  -> 10.30.0.0/16
```

## Current Design Decisions

This version uses:

- **Single AWS account:** `866934333672`
- **Separate VPC per environment**
- **Separate ECR repositories per environment**
- **Branch-based deployment:** `dev`, `uat`, `production`
- **No Cognito**
- **No Google/Facebook social login**
- **Local username/password authentication in FastAPI**
- **bcrypt password hashing**
- **JWT application tokens**
- **JWT signing secret generated by Terraform and stored in Secrets Manager**
- **RDS-managed MySQL master password stored in Secrets Manager**
- **ACM certificate for HTTPS**
- **Route 53 DNS records**
- **Production GitHub Environment approval gate**
- **PR guard:** only `dev -> uat` and `uat -> production` are allowed

## Authentication Design

This project does **not** use Cognito.

Authentication is implemented in the FastAPI backend.

```text
User creates account
  |
  v
POST /api/auth/register
  |
  | password is hashed with bcrypt
  v
RDS MySQL users table

User signs in
  |
  v
POST /api/auth/login
  |
  | password is verified
  v
FastAPI issues JWT token
  |
  v
Frontend stores token and calls protected APIs
```

The JWT secret is generated by Terraform and stored in AWS Secrets Manager.

```text
Secrets Manager:
  react-js-application/dev/auth/app-jwt
  react-js-application/uat/auth/app-jwt
  react-js-application/production/auth/app-jwt
```

## VPC Design

Each environment gets its own VPC. Terraform creates the VPC, subnets, route tables, Internet Gateway, NAT Gateways, and VPC endpoints where applicable.

| Environment | Branch | VPC Name | CIDR | Region |
|---|---|---|---|---|
| Dev | `dev` | `vpc-dev` | `10.20.0.0/16` | `us-east-1` |
| UAT | `uat` | `vpc-uat` | `10.10.0.0/16` | `us-east-1` |
| Production | `production` | `vpc-production` | `10.30.0.0/16` | `us-east-1` |

Terraform dynamically selects 3 available Availability Zones:

```hcl
data "aws_availability_zones" "available" {
  state = "available"
}

locals {
  selected_availability_zones = slice(data.aws_availability_zones.available.names, 0, var.az_count)
}
```

Each VPC has:

```text
3 public subnets
3 private frontend subnets
3 private backend subnets
3 private database subnets
```

## ECR Repository Design

Each environment has its own frontend and backend ECR repositories.

```text
react-js-application/dev/react-frontend
react-js-application/dev/fastapi-backend
react-js-application/uat/react-frontend
react-js-application/uat/fastapi-backend
react-js-application/production/react-frontend
react-js-application/production/fastapi-backend
```

Every application deployment pushes two image tags:

```text
latest
<environment>-<git-sha>
```

Example:

```text
866934333672.dkr.ecr.us-east-1.amazonaws.com/react-js-application/dev/react-frontend:latest
866934333672.dkr.ecr.us-east-1.amazonaws.com/react-js-application/dev/react-frontend:dev-a1b2c3d...
```

The EC2 instances deploy only from the environment repository’s `latest` tag.

```text
Dev ASG pulls:        react-js-application/dev/*:latest
UAT ASG pulls:        react-js-application/uat/*:latest
Production ASG pulls: react-js-application/production/*:latest
```

The Git SHA tag is retained for audit and rollback reference.

## PR Promotion Guard

The tooling workflow includes a PR guard that allows only:

```text
dev -> uat
uat -> production
```

It blocks:

```text
dev -> production
feature -> uat
feature -> production
production -> uat
uat -> dev
```

Configure branch protection for `uat` and `production`:

```text
Repo -> Settings -> Branches -> Branch protection rules
```

Enable:

```text
Require a pull request before merging
Require status checks to pass before merging
Require branches to be up to date before merging
```

Required status check:

```text
Validate PR Promotion Path
```

## GitHub Actions Workflows

### 1. Tooling Foundation

File:

```text
.github/workflows/tooling-foundation.yml
```

Creates:

- Terraform state S3 bucket
- DynamoDB state lock table
- KMS key for Terraform state
- GitHub OIDC provider
- GitHub bootstrap role
- PR promotion guard job

The first run uses temporary AWS access keys.

After tooling is created, delete the temporary access keys from GitHub Secrets.

### 2. Bootstrap Single Account

File:

```text
.github/workflows/bootstrap-single-account.yml
```

Creates:

- `react-js-application-dev-github-actions-deploy-role`
- `react-js-application-uat-github-actions-deploy-role`
- `react-js-application-production-github-actions-deploy-role`
- Environment-specific ECR repositories
- SSM SecureString parameters for deploy role ARNs

### 3. App Deploy

File:

```text
.github/workflows/app-deploy.yml
```

Runs on push to:

```text
dev
uat
production
```

The workflow:

1. Resolves the environment from the branch.
2. Reads the environment deploy role ARN from SSM.
3. Builds frontend and backend Docker images.
4. Pushes images to the environment-specific ECR repositories.
5. Tags images as `latest` and `<environment>-<git-sha>`.
6. Runs Terraform plan.
7. Runs Terraform apply.
8. Refreshes the frontend and backend Auto Scaling Groups so new instances pull `latest`.

## Security Controls

This project includes:

- GitHub OIDC authentication
- No long-lived AWS keys after tooling bootstrap
- KMS-encrypted Terraform state
- DynamoDB state locking
- Environment-specific deploy roles
- Environment-specific ECR repositories
- Private EC2 instances
- Private RDS MySQL
- RDS-managed database password in Secrets Manager
- Application JWT secret in Secrets Manager
- KMS encryption for RDS, EBS, Secrets Manager, SSM, and state
- HTTPS using ACM certificates
- HTTP-to-HTTPS redirect
- Security group tier isolation
- Production approval gate
- PR branch promotion guard

## Operational Notes

- Run tooling first.
- Run bootstrap second.
- Deploy dev before uat.
- Deploy uat before production.
- Do not commit real secrets.
- Do not expose RDS publicly.
- Use SSM Session Manager instead of SSH.
- Use `latest` only inside the environment-specific ECR repository.
- Keep Git SHA tags for traceability and rollback.
- Refresh ASGs after image updates so EC2 instances pull the latest image.

---

## Final Summary

This project deploys a secure AWS 3-tier React and FastAPI application into a single AWS account using separate VPCs, separate ECR repositories, HTTPS, Route 53, ACM, RDS MySQL, Secrets Manager, and GitHub Actions automation. It uses local username/password authentication with bcrypt and JWT, and it enforces controlled promotion through `dev -> uat -> production`.
